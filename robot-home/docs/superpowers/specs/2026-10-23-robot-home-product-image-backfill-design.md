# 机器人产品图片补全设计

日期：2026-10-23
范围：机器人之家公开 PC/小程序共用的机器人封面与详情图库。

## 现状

- 生产 API 返回 56 个机器人型号。第一页 20 个型号的 `coverImage` 都为空；Atlas（机器人 ID 126）的 `/api/robots/126/images` 返回空数组。
- 图片组件已正常用 `coverImage` 和 `robot_image` 渲染占位图，问题是生产数据缺少图片，不是 CSS 或图片加载逻辑。
- 机器人之家生产存储目前是本地 `/files`；它自己的 MinIO 配置项没有设置。
- mall 已有 MinIO 公共 bucket `mall-public`，外部 URL 前缀为 `https://mall.21zuo.com/minio/mall-public`。bucket 目录禁止列举，单个不存在的对象返回 404，符合公开对象而非公开列目录的访问方式。

## 设计

1. **图片来源**：逐型号核对制造商/品牌官方产品页或官方媒体素材，确认名称和型号吻合后才采用。保留来源页面 URL、robot ID、型号、文件 SHA-256 和目标对象 URL 的清单，方便复查来源与重复执行。无法确认型号、来源或可用性的记录留空并列为待补，不用 AI 示意图或相似型号照片冒充。
2. **存储**：不切换机器人之家的整套文件上传配置，也不改 MinIO bucket policy。图片写入现有 `mall-public` bucket 的独立前缀 `robot-home/robots/{robotId}/`，数据库保存可公开访问的 `https://mall.21zuo.com/minio/mall-public/robot-home/robots/{robotId}/...` URL。上传凭据只在受控执行期间从现有服务器配置读取，不写入代码、清单或日志。
3. **数据写入**：仅处理生产中封面为空或详情图库缺图的型号；保留所有已有非空封面和图片行。每个型号的封面写入 `robot.cover_image`，已核实的不同角度/场景图写入 `robot_image`，按稳定顺序排列。重复运行不得重复插入相同对象或覆盖既有有效图。不得修改机器人名称、价格、参数、状态等字段。
4. **公开访问与验证**：写入前验证文件类型、尺寸、真实图像解码和型号匹配；上传后对每个目标 URL 做 HTTP/MIME/解码抽检或全量检查，再通过生产 API 确认封面和图库已返回。报告成功数量、未能匹配数量和所有未改动项。只有来源可信且匹配的型号才计为完成。
5. **安全与回退**：写数据库前生成新的 robot_home 备份并验证压缩包；先保存待执行的 ID/URL 变更清单。若数据回填异常，恢复本次涉及的 `robot.cover_image` 与 `robot_image` 记录，或经确认后使用备份；MinIO 对象先保留，不自动删除，以免误删其他引用。

## 验收标准

- 56 个型号逐一盘点，封面缺失项有明确的完成/跳过原因。
- 本次新增封面均来自可追溯、与型号准确对应的来源；没有 AI 或相似机型替代图。
- 所有新写的公开对象可通过 HTTPS 读取，Content-Type 与图片格式一致且能解码。
- 数据变更仅限图片字段/图片行；现有非空图片与其他产品字段保持不变。
- PC 机器人列表/详情和小程序复用的 API 都能得到新图片 URL；此前失败的缺图样例不再渲染“暂无图片”。
- 交付图源清单、备份位置、变更计数、异常型号和验证结果；不提交 MinIO 密钥或临时凭据。

## 约束与限制

- 制造商网页公开展示不自动代表图片已获再发布许可；实施时保留来源并遵守页面标注的使用条件，遇到明确限制则跳过并报告。
- 此次不启用机器人之家的 MinIO adapter，不改变服务配置、bucket 权限或 Nginx 路由；若现有公开对象 URL 无法在浏览器读取，先停止回填并报告，不扩大到存储架构改造。
- 已有的全站未提交开发改动必须保留；实施只改本任务需要的清单/数据，不提交或推送其他开发改动。
