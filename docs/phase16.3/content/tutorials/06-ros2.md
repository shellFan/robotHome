# ROS 2 入门：节点、通信与控制接口

**内容状态：原创草稿，待技术与后台审核；未发布。**

## 1. ROS 2 的位置

ROS 2 是机器人软件的通信、集成和工具生态，不是实时操作系统，也不会自动提供功能安全。一个机器人程序通常由多个进程或组件组成，它们通过 ROS 图中的节点、话题、服务和动作交换数据。

## 2. 选择合适的通信方式

- **Topic** 适合连续数据流，例如关节状态、图像或里程计；发布者与订阅者不要求同时存在。
- **Service** 适合短请求与响应，例如查询状态或触发一次简单操作。
- **Action** 适合耗时任务，可反馈进度并支持取消，例如导航到目标点。

通信能否稳定工作还依赖域发现、网络、多播、防火墙、消息类型和 QoS。可靠性、历史深度、持久性等 QoS 设置不匹配时，节点可能已经发现对方但仍收不到预期数据。

## 3. 从 talker/listener 到机器人模型

先安装受支持的发行版并运行官方 talker/listener 示例，再练习 `ros2 node list`、`ros2 topic list`、`ros2 topic echo`、`ros2 service list` 和 `ros2 action list`。接着学习工作空间、包、参数、launch、TF 坐标变换、RViz 和 rosbag。URDF 描述连杆与关节；它是模型文件，不会自动生成准确的实体几何、碰撞模型或硬件驱动。

## 4. 连接控制系统

`ros2_control` 提供控制器与硬件接口之间的框架。先用 mock hardware 或仿真验证关节名称、命令接口、状态接口、控制器生命周期和限位，再连接真实设备。真实硬件还需遵循厂商接口、控制周期和安全说明。通信框架或仿真测试不能替代实体机器人的独立安全功能。
